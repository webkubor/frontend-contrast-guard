# 决策预览参考

只在设计方向会实质影响品牌、产品定位或关键交互，且现有需求与项目资料无法推断用户意图时使用本流程。字号、边距、常规组件样式等可逆实现细节由已获授权的 Agent 自行决定并记录，不应为偏好细节阻塞任务。

## 需要用户决定时

1. 尽量在真实项目页面或隔离预览分支中呈现候选方向。候选应体现实际布局、层级、色彩和关键组件，不只给色板或文字描述。
2. 在当前环境生成可打开的页面预览或截图，并标明视口、主题、语言及使用的数据状态。区分真实实现和静态概念稿。
3. 给出最多 2–3 个互斥选项，说明各自适用的产品意图、取舍和推荐项。用户可以选择“按默认推荐继续”或补充方向。
4. 将决策请求放在当前会话或项目使用的用户沟通渠道中。不要假设可访问某个专有决策系统、设备或聊天平台。
5. 收到选择后记录方向和日期到项目 `DESIGN.md`，继续实现、浏览器验证与交付。

## 无法预览或无需阻塞时

- 预览工具不可用：提供当前可复现的截图、页面地址或低保真示意，并如实说明缺失的渲染条件；不得声称已经打开真实页面。
- 任务授权 Agent 自主完成，或暂时拿不到偏好反馈：根据用户需求、项目设计契约和现有产品做推荐决策，在 DESIGN.md 中标注为推断并继续；可逆方向后续可调整。
- 用户没有提出需要决策的关键方向：跳过本流程，直接实现和复查。

## 请求模板

```text
需要决定：<会显著影响品牌/产品方向的事项>
推荐：<选项>，因为 <与产品目标和现有证据的关系>
A. <方向与主要取舍>
B. <方向与主要取舍>
预览：<真实可打开地址或截图路径；标明视口/主题/状态>
选择 A、B，或授权我按推荐继续。
```

此文件描述的是决策方法，不代表仓库自带预览服务器、用户沟通工具或截图服务。
