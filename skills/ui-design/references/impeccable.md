# Impeccable 执行器参考

`impeccable` 是可选的 UI 执行工具；`ui-design` 始终是任务入口，项目的需求、设计契约和实际页面才是决策依据。若环境未安装该 skill 或其命令不可用，直接按 ui-craft 流程完成工作，不要把安装它作为前置条件。

## 什么时候使用

- 需要在现有方向上细化排版、布局、颜色或交互：按需使用 `polish`、`typeset`、`layout`、`colorize`、`harden`、`adapt`、`optimize`。
- 想发现实现中的 UX / accessibility / responsive 问题：使用 `audit` 或 `critique`。
- 想扫描 HTML/CSS 中的常见 AI UI 模板反模式：使用 `detect`，然后人工结合项目上下文判断命中。
- 需要整理需求和产品背景：`shape` / `init` 可辅助访谈，但用户已授权实现时，不需要等待偏好性确认。

具体命令、参数和能力边界以本环境已安装的 Impeccable skill 文档为准。不要在本仓复制其脚本或假设所有 Agent harness 都使用相同安装路径。

## 四种视觉力度参考

| Mode | 常见任务 | 选择原则 |
|---|---|---|
| Persuade | 营销页、品牌叙事 | 允许鲜明视觉重点，同时保证信息和行动清晰 |
| Operate | 后台、工具、工作台 | 让内容、密度和效率优先，保留品类熟悉度 |
| Read | 文档、阅读内容 | 优先长文可读性与稳定排版 |
| Experience | 沉浸式消费体验 | 交互和动效服务于产品目标 |

以用户 brief 和项目设计契约选择 mode；它只是执行尺度，不替项目决定色板、字体或组件体系。

## 执行边界

- 用户要求和项目 `DESIGN.md` 优先于执行器的默认建议。
- 精修应当保留已确认的方向；只有任务确实要求重设计时才重选方向。
- `detect` 是静态反模式提示，不是质量裁决；检查记录、对比度和渲染截图关注的问题不同，可以按需组合。
- Agent 已获授权完成时，记录推断与取舍并继续。只有关键产品方向无法从需求和项目证据判断时，才请求用户选择。
- 任何修改最终都在真实页面检查。工具输出不替代浏览器复查。
