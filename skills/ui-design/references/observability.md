# 可观测细则

UI 交付要能检查真实页面和运行行为，但不要求每个项目引入同一套工具。先使用项目已有的浏览器、日志、错误上报与性能监控能力。

| 需要观察什么 | 最低可用证据 | 工具如何选择 |
|---|---|---|
| 页面结构与视觉 | 可复现页面地址、视口/主题/状态、真实截图 | 使用当前环境可用的浏览器自动化或人工浏览器 |
| 交互与错误 | 关键交互结果、控制台错误、API 失败线索 | 复用项目现有测试、浏览器工具或运行时日志 |
| 部署版本 | 当前页面版本，以及切换部署后的更新表现 | 遵循项目已有更新检测与错误兜底方案 |
| 性能 | 页面、视口、网络条件下的 LCP / INP / CLS 基线和复测 | 使用浏览器 DevTools、web-vitals 或项目已有监控 |

## 复测记录

至少记录：页面/路由、版本或 commit、视口、主题、语言、登录/数据状态、截图位置、验证步骤、观察结论与未测项。对比前后截图时固定这些条件。

## 使用原则

- 需要登录或连接真实服务的浏览器测试必须遵循项目授权与脱敏规则；不要把凭证写入截图、日志或公开记录。
- 截图应由 Agent 或评审者实际打开检查。采集截图或 DOM 本身不等于完成视觉评审。
- 工具不可用时写清具体环境限制和未验证范围；不要用成功的本地请求或 HTTP 状态码冒充目标环境验收。
- 不为满足本 skill 而重复安装日志、错误上报或版本更新产品；已有等价能力优先。
